## Findings (one commit each)

1. **SEC-06 redirect policy** — `packages/core/src/http-utils.ts:288` leaves `redirect` at the default `follow`: fetch strips Authorization cross-origin but NOT the body, so a compromised endpoint answering PUT with `307 Location: attacker` receives the full sync document. Rust WebDAV already hardens this (`apps/desktop/src-tauri/src/sync.rs:1164` custom policy) but Rust `blocking_http_client` (`:1138`, cloud GET/PUT at `:3315/:3360`) inherits `Policy::limited(10)`. FIX: `redirect: 'error'` for write methods in `fetchWithTimeout` (reads may keep follow); give the Rust cloud client the same custom policy shape as `webdav_blocking_http_client`. Red tests: TS — a 307 on PUT rejects without a second request (mock fetch); Rust — mirror the existing webdav policy test for the cloud client.
2. **SEC-10a mobile expo-file-system upload bypasses the cleartext guard** — `apps/mobile/lib/attachment-sync-backends/common.ts:224` (`uploadWebdavFileWithFileSystem`) PUTs with a hand-built Basic header and never calls `assertConnectionAllowed`; the nearby guard's throw is swallowed to a warning (`attachment-sync-backends/webdav.ts:110-113`). FIX: call `assertConnectionAllowed(url, …, {…SYNC_LOCAL_INSECURE_URL_OPTIONS, allowInsecureHttp})` at the top; make the swallowed guard rethrow. DO NOT touch the Android network-security-config or manifest cleartext flags — `cleartextTrafficPermitted="true"` in the base config is LOAD-BEARING for private-IP WebDAV (#663, settled); the JS-level guard is the enforcement point. Red test: http URL + opt-in off → typed refusal before any request.
3. **SEC-12a one redactor for user-visible sync errors** — `packages/core/src/sync-service-utils.ts:101` `sanitizeSyncErrorMessage` covers headers/tokens but not URL userinfo; `redactSensitiveText` (`log-sanitize.ts:83`) already handles it (`:69-70`). Rust error strings interpolate the WebDAV URL verbatim (`sync.rs:3126,3248`). FIX: delegate `sanitizeSyncErrorMessage` to `redactSensitiveText`; strip userinfo in the two Rust formatters (reuse/port the existing redaction helper if one exists in Rust — search first). DEFERRED (recorded, do not do here): moving URL userinfo into the keyring at config-save time. Red tests: TS + Rust message with `https://user:pass@host/` → no `pass` in output.
4. **SEC-16 mobile diagnostics log content leak** — `apps/mobile/lib/attachment-sync-backends/webdav.ts:143`, `lib/attachment-sync-utils.ts:575,596`, `attachment-sync-backends/cloudkit.ts:93` log `attachment.title` and raw `uri`, violating the #854 invariant ("ids and field names only, never task content", stated at `apps/mobile/lib/sync-service.ts:907`). FIX: log id + extension/size; pass uris under `*Url` keys so `sanitizeUrl` applies (check `log-sanitize.ts` key handling), or add title/uri to `shouldRedactKey`. Red test: capture log context from one call → no title text.
5. **BUG-23 weak-fingerprint option not plumbed to mobile PUT/HEAD** — `apps/mobile/lib/sync-service.ts:732` resolves `allowWeakFingerprint`, passes it to webdavGet (`:1228`) but not webdavPut (`:1287`) / webdavHead (`:1320`); core takes strict only on explicit `=== false` (`webdav.ts:143`); mobile has a reader for `WEBDAV_ALLOW_WEAK_FINGERPRINT_KEY` but NO writer. DECISION (fixed, automatic-beats-manual): plumb the resolved value to all three calls for consistency; do NOT add a mobile toggle — desktop's setting exists (`sync-service-config.ts:63`), mobile inherits default behavior; leave the key reader in place (harmless compat). Red test: mobile sync-service test asserting the option reaches PUT and HEAD request options.
