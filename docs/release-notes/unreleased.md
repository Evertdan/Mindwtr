# Mindwtr Unreleased

Changes collected after `v1.2.1` and before the next version tag.

## Highlights

- Mobile reminder rescheduling no longer rewrites its stored alarms or queries the system alarm list after every edit, and very large libraries stop re-serializing the whole library for a backup they already know is too big to keep.

## Full Change List

- Large libraries: editing, completing, or adding a task now redraws lists noticeably faster. Sorting a list and rebuilding the counts behind it were re-reading the same dates thousands of times per keystroke-sized change; both now read each date once. (#766)
- Desktop: right-clicking one task and then another no longer leaves the first row wearing the highlight ring — dismissing a context menu with the pointer no longer snaps keyboard focus back to the old row. Closing the menu with Escape still returns focus to where you were. (#999)
- Desktop: the sync backend state file in your profile folder is now called `sync-backend-state.json`. It tracks whichever sync backend you picked, not just Dropbox, so the old Dropbox-specific name was misleading; existing profiles are renamed automatically on the next launch. (#1007)
- Desktop: a date field now shows a warning outline while the typed text isn't a date it can read. Nonsense never saved — it quietly reverted when you left the field — but nothing said so while you typed. (#1050)
- Desktop: the ➔ button on Waiting and Someday rows now shows a "Move to Next" tooltip on hover, and clicking it shows the same "moved to Next" toast with Undo that completing a task gets — the task no longer just vanishes from the list. (#1053)
- Pomodoro: the "Focus sessions completed" count now resets automatically at midnight and shows today's sessions, on desktop and mobile. It used to grow forever with no way to reset it. Time already credited to tasks is unaffected.
- Desktop: hovering or clicking a link in a task no longer makes the app's embedded browser engine quietly pre-connect to the linked site. Links always opened through your default browser; the engine was still warming up DNS and TLS connections to the target on its own. Link text now carries no browser-visible URL, so there is nothing left for the engine to speculate on — the URL shows in the hover tooltip and opens exactly as before. (#913)
- Mobile: checklist items can now be added straight from the two places that already show a checklist — the expanded checklist under a task row in a list, and the task preview. Type an item, press return, and the field clears with the keyboard still up for the next one, so a shopping list no longer needs a trip through the task editor's edit tab for every line. (#1055)
- Android: the Complete, Snooze, and Dismiss buttons on reminder notifications no longer go silently dead when the reminder's internal alarm record was already cleaned up — typically a notification left sitting in the tray overnight while the app rescheduled its reminders. Tapping such a button now always at least clears the notification, Complete still completes the task, and the receiver logs every tap so future reports are diagnosable. Dismissing a repeating reminder also reliably stops its sound now. (#1028)
- Desktop: section notes now show as a one-line preview right under the section header, in both the list and board layouts, so per-section guidance (like a project template's planning prompts) is visible without clicking the notes icon on every section. Hovering the line shows the full text; opening the notes editor hides the preview while you type.
- Duplicating a project now keeps reference items as references. They used to turn into Next actions along with everything else, so template projects carrying explanatory reference material gained fake to-dos on every copy. Actionable tasks still reset to Next with cleared dates and checklists, as before.
- Mobile: tapping the check icon on a search result now completes the task right there, with an Undo toast — it used to be decoration, forcing a detour through the task preview's status picker. Finished tasks show a tinted check instead. (#1051)
- Desktop: file attachments that point outside the app's managed folder now show an Edit button in the task editor, so a link added before the pointer fix can actually be re-saved into a true pointer — previously the promised Edit affordance only appeared on attachments already typed as links. Converting one also drops the leftover synced-copy bookkeeping, and once the conversion saves, the stray copy the app had restored into its own attachments folder is deleted too. (#1001)
- Desktop: machines without a usable keyring no longer show a "Failed to check Dropbox connection status" banner when Dropbox was never set up — the status check now answers "not connected" instead of erroring when no Dropbox credentials were ever stored. A real Dropbox setup with an unreachable keyring still reports the error. (#1043)
- Desktop: tasks in the calendar's "Plan next actions" panel can now be dragged straight onto a day, matching the Schedule button and the drag support task lists already had. (#493)
- Desktop: File-backend sync no longer fails with "Failed to acquire an exclusive sync lock … Function not implemented" on filesystems that don't support OS file locks. Sync proceeds without the lock there — the pre-1.2 behavior — and logs a warning instead. (#1036)
- Windows: the app log now records the exact browser-argument set WebView2 was launched with, including anything merged in from your own `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` value, so network-behavior reports can be checked against what actually applied. (#913)
- Mobile: the project menu's manual "Order" entry no longer disappears while a custom Sort is active — it now shows greyed out with an "Available when Sort is Default" hint, so manual reordering stays discoverable instead of looking like a missing feature.
- Desktop: a Dropbox setup whose credentials can't be read (for example a sandboxed install with the keyring blocked) no longer re-shows the "Failed to check Dropbox connection status" pop-up on every settings visit and sync check — the failure is reported once, and again only if it changes or comes back after a recovery. (#1060)
- Linux: the app window now shows its icon in X11 taskbars and window lists even without desktop integration — GTK silently rejects window icons as large as the one the app was setting, so panels that couldn't fall back to an installed launcher entry (like Cinnamon showing a plain AppImage) drew a blank space. (#1018)
- Quick add now understands natural-language dates in your own language when the app runs in German, Spanish, French, Italian, Japanese, Dutch, Portuguese, Russian, Swedish, or Chinese — "Appeler le dentiste vendredi prochain" detects next Friday the same way "next friday" always has, and `/due:demain` works like `/due:tomorrow`. English phrases keep working in every language, and languages without a parser keep today's English-plus-numeric behavior. (#1059)
- Android (FOSS builds): the FOSS APK build now applies the same dependency fixes as the Play build. It turned out the FOSS build recipe silently skipped every patched dependency — which is why sharing an email from FairEmail still captured the body as the task title on FOSS installs even after 1.2.0 claimed to fix it. The subject-as-title fix (and the other patched-dependency fixes) now genuinely ship in FOSS APKs, and a patch that fails to apply now fails the build instead of shipping unpatched. (#1016)
- Focus now has an "Upcoming" section, on desktop and mobile: tasks that are deferred by a start date — and recurring tasks waiting for their next date — show there for the week before they surface, sorted by the day they'll appear. No more being surprised by a recurring task the day it lands; the section only appears when something is coming, and collapses like the others. (#1061)
- Android: fixed a native crash (SIGSEGV in the SQLite bridge) that could hit when a database query finished right as the app was shutting down or restarting — the query's completion was delivered to the new JavaScript runtime while still holding handles from the old one. Seen on Play Console from Pixel Fold and Galaxy Tab devices on 1.2.1.
- Desktop: a task with a deadline on the calendar now carries its project's color (or its area's) on the chip's colored edge, the same way external events carry their calendar's color — so a month at a glance shows which project each deadline belongs to. Tasks with no project or area keep the red edge. Month, week, schedule, and the day panel.
- Android: adding a checklist item in the task editor no longer jumps the form back to the top of the checklist — the view stays put and the keyboard opens on the new row. The new row was being focused before it had a position on screen, so Android's scroll-into-view aimed at the wrong spot.
- Sync can now be encrypted with a passphrase, for the backends that store files you can see — File Sync, WebDAV, and Dropbox. Settings → Sync gains an Encryption section: turn it on with a passphrase (or generate a strong one), and everything the app puts in the sync location — the data file, its backups, snapshots, and attachments — is encrypted before it leaves the device; merge behavior and what other devices see in the app are unchanged. Devices without the passphrase pause syncing and ask for it once; a wrong passphrase never touches the stored files. Update every device to this version before enabling — older versions cannot read the encrypted files. Self-hosted cloud and iCloud sync are not covered, and the passphrase is unrecoverable by design. (#1056)
- Attachments now follow the file: editing an attached file after attaching it propagates the new content through sync — each sync cycle notices a changed local file (modification time and size, confirmed by content hash), re-uploads it, and other devices re-download it. Previously an attachment was a one-time snapshot and edits stayed on the device that made them. Detection of linked (external-path) files is desktop-first; phones re-download updates everywhere and detect edits to files in the app's own storage on File Sync, WebDAV, and iCloud. Two devices editing the same file still resolve whole-file last-writer-wins. (#1057)
- macOS: the desktop app now ships its own widget. Adding a Mindwtr widget from the Mac widget gallery shows today's focus tasks and clicking it opens the desktop app — previously the gallery only offered the iPhone's widget over Continuity, which opened the app on the phone instead. The Mac widget also takes precedence over the iPhone one in the gallery. (#1054)
- Desktop: Focus, Inbox, Next actions, Waiting, and Someday each remember their own "Group by" choice now. Picking a grouping on one of them used to change it on all five, so grouping Focus by project also regrouped the Inbox. Your current grouping carries over to every one of these lists on first launch, then they go their separate ways. (#1063)
- Recurring tasks: a monthly or yearly task whose start and due fall on different days no longer has its start pulled onto the due date's day-of-month. Completing "starts the 14th, due the 15th" now creates "starts September 14, due September 15" instead of a copy starting August 15 — a leftover from recurrences saved before start and due tracked their anchor days separately. Desktop, mobile, and the local automation API.
